# Per-page layout-MM ASCII DXF geometry review backend

Status: ISOLATED_MM_DXF_GEOMETRY_REVIEW_READY_FOR_G. Output is PARTIAL/HUMAN_CHECK_REQUIRED or BLOCKED, product Gate HOLD. Actual Jw Open/Edit/Save/Round-trip NOT_RUN.

`drawingIRToReviewDXF(adapterEnvelope)` consumes the fixed candidate.2/B2 envelope and validates the exact pinned IR contract independently. It rejects promoted readiness, real-world/calibration claims, unknown transform scope, physical-unit/frame/axis mismatches, unsafe numbers, broken global source/part denominators and page partition/order mismatches. It does not authenticate an untrusted producer's source claims: the immutable G2 source qualification and independent G DXF source oracle remain required.

Only existing `drawingGeometry` in each source page's MM/LAYOUT/UP frame is serialized. No EMU conversion, Y reflection, calibration or rotation is applied again. Source numeric conversion has already been validated as EMU/36000 followed by explicit page-height reflection. Rotated/grouped rectangle corners retain all ordered vertices. Source declaration rotation metadata stays source metadata and is not applied twice.

Targets: line -> LINE; polygon/polyline -> classic POLYLINE, ordered VERTEX records, SEQEND; axis rect -> four-corner closed POLYLINE; circle -> CIRCLE. Closed flag 1 and open flag 0 distinguish closure. Ellipse/arc/text and all original unsupported/hidden/background/custom/inherited/uncertain parts receive explicit target ledger rows, with no approximation, rasterization or invented placement.

The file header declares `$ACADVER=AC1009` and no automatic import-unit header. Version is a format label, not proof of R12/actual Jw compatibility. `$INSUNITS` and newer truecolor/lineweight tags are omitted. Coordinates are numerically layout MM; every manifest ledgers UNIT_HEADER_METADATA_UNAVAILABLE and requires actual Jw mm-import and known-length verification. No real-world dimensions or actual-app tolerance are claimed.

Display is a generated, explicitly hashed policy: VDRAW_REVIEW_GEOMETRY layer, ACI 7, CONTINUOUS review outlines. This is not source color/fill/width/dash/opacity/font fidelity. No truecolor-to-ACI approximation occurs. Every inventory row has six field loss records; all original source XML/text/style/source binding data remain in machine-readable evidence. Explicit source no-stroke may gain a review outline under policy; fully no-paint sources may be shown for review, with separate outline/visibility override flags.

Each page receives a separate filename based on the full source hash and page index, exact ASCII byte SHA256, stable logical entity IDs and individually mapped raw handles. Logical POLYLINE count differs from raw POLYLINE/VERTEX/SEQEND counts. All required inventory rows remain global in every per-page evaluation. Other-page rows explicitly reference that separate artifact's filename/hash under the partition policy. Source infrastructure stays preserved in the manifest with explicit non-drawable policy rows. Target ellipse omissions and all original unsupported parts remain counted. PARTIAL/BLOCKED evaluated IR passes the pinned validator; FULL never follows.

New checks are backend-only: the complete focused suite is 33 named tests, not a rerun of completed A/B/G suites. Synthetic open-polyline and ellipse-only contract witnesses test serialization/gating and are not original-source accuracy evidence. Six immutable G-qualified/native QA/synthetic envelopes produce 22 logical entities / 82 raw entity records over 7 page files, out of the unchanged 32 original geometry components. The previously represented IR ellipse is separately unsupported here. Source appearance remains unqualified.

Frozen fixture DXF bytes, full manifest, property loss ledger, source/entity mapping and evaluated IR are saved under tracks/B/mm-dxf-evidence. The next step is G independent parsing of actual bytes and original source mathematics. This module is isolated from editor/UI/storage/signing/APK/product routes.

Format references: [Autodesk archived R12 DXF reference](https://damassets.autodesk.net/content/dam/autodesk/www/developer-network/platform-technologies/autocad-dxf-archive/acad_r12_dxf.pdf), sections Entity Groups/POLYLINE, Group Codes Common to Entities and Comments. It documents the classic vertex sequence, closure bit and comment/common-entity fields used here. These definitions do not establish actual Jw compatibility. [Autodesk header reference](https://help.autodesk.com/cloudhelp/2021/ENU/AutoCAD-DXF/files/GUID-A85E8E67-27CD-4C59-BE61-4DC9FADBE74A.htm) distinguishes version identifiers and drawing-unit metadata; this backend omits automatic import-unit metadata.
