## Result

`VisionJobs.receive` preserves the named `drawing-WxH` coordinate frame. Received candidates retain `sourceWidth`, `sourceHeight`, and the uniform image `referenceImageTransform` (contain scale and centered offsets). Candidate `sourceBinding` records document/page/source ID, PDF page number, actual work-image dimensions, and an image change detector. It remains on saved/reloaded candidates; preview/adoption refuse a different document, page, source, changed source image, or missing/unknown coordinate metadata.

The image dimensions come from the actual sanitized PNG IHDR, including pre-metadata saved projects. Photo/PDF import currently creates sanitized PNG work images, so no import pipeline or source copying is changed. A no-image operation sample uses its known synthetic canvas. Real photo/PDF sources without an identifiable PNG work image are refused. An external candidate's supplied source dimensions/page fields must match the current bound source.

`VisionJobs.preview(doc, candidate)` returns the bound candidate page frame and its source. The sole shared `app.js` change uses this result in `candidatePreview`, rather than combining candidate coordinates with the active page canvas. No output generation, export UI, ownership, busy, save, or engine code is changed.

Adoption creates the existing 1200x800 new page. It converts candidate coordinates through the same `xMidYMid meet`/contain mapping used by the SVG source photo. One uniform scale applies to x/y/w/h, vertices, font size and stroke width. Circle arcs remain circles. Text, explicit dimensions, angles, provenance category, and UNSCALED calibration are not promoted or inferred. The full prospective document is validated before mutating the caller's document; the source page is preserved.

Examples:

- 2000x1000 candidate, photo 2000x1000, point (600,400) -> adopted page point (360,340), scale 0.6 and photo Y offset 100.
- Existing provider `drawing-1200x800` on that same photo -> 1200x800 preview/adoption is identity, preventing a second transform.
- Square, portrait, landscape and non-3:2 photos use the corresponding centered contain offsets.

## Compatibility and limits

- Existing fixed `drawing-1200x800` provider envelopes remain supported. Missing physical image dimensions are recovered from the local work PNG at receipt, not guessed from an unrelated page.
- Unknown coordinate units, missing coordinate frames, or old saved candidates without complete binding/transform metadata are not adopted. The saved candidate and original page remain intact; the user must recreate a candidate from the source.
- A saved candidate may be reopened on its original bound page. Opening it on its adopted page or another page is intentionally refused; another adoption requires returning to the original source page. This avoids stale preview/adoption against a different page.
- The source fingerprint is a local change detector, not a cryptographic proof that an external AI provider saw a particular image. No real AI quality, external provider inference, or Android behavior is asserted.
- No new JS module is introduced, so the existing service-worker asset list remains sufficient for this change. Cache invalidation for the combined release belongs to integration.
- The engine's independent abnormal-angle fix is still required. This branch does not replace or alter its validation contract.
